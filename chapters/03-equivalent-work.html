Chapter 03Chapter outlineLab planned

Are they doing the same work?

Are the systems returning equivalent answers under comparable conditions and guarantees?

This is a chapter outline. The worked example and executable lab are planned. You can use the design task below to start your benchmark brief.

What you will learn

  • Define the expected output before timing.
  • Audit indexes, configuration and service guarantees.
  • Repair a comparison whose apparent advantage comes from different work.

01 / The question

Start with a customer decision

One query looks faster, but one database has an index and the other does not. A second comparison returns fewer rows on one side.

02 / Worked example · planned

The comparison to build

Inspect a deliberately incomplete comparison brief. Separate query correctness, tuning choices, deployment constraints and guarantees, then document the comparison being made.

03 / Experiment · planned

How the lab will work

  1. Check results against a deterministic fixture, including nulls, duplicates and boundary values.
  2. Record index creation and input preparation separately from query execution.
  3. Change one configuration while preserving the stated comparison contract.

The executable lab, reference outputs and progressive hints will be added when this chapter is implemented.

04 / Design task

Start your benchmark brief

Produce a fairness checklist for your database comparison. Name which conditions must match and which differences are legitimate parts of the decision.

05 / Keep the evidence

What your record should contain

  • Expected outputs and correctness checks
  • Index, resource and configuration records
  • A statement of the guarantees and permitted differences

06 / Interpret

What the evidence can support

Equal option names do not establish equal guarantees. A correctness check on a fixture supports that fixture; describe additional checks needed for the intended workload.
