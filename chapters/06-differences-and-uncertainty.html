Chapter 06Chapter outlineLab planned

How much faster—and how certain?

We’ll repeat the database comparison and examine how much the results change between runs. A small lead in one run may disappear in the next. You’ll learn to describe both the size of a difference and how much confidence the evidence gives you.

This is a chapter outline. The worked example and executable lab are planned. You can use the design task below to start your benchmark brief.

What you will learn

  • Distinguish repeated independent runs from samples within one run.
  • Compare distributions and calculate clearly defined ratios.
  • Describe uncertainty without treating an inconclusive result as a win.

01 / The question

Start with a customer decision

Even with the same workload and runner, timings vary. Other activity on the device, engine startup and cached data can affect a run. Before saying one option is faster, we need to see whether the difference persists when we repeat the experiment.

Suppose one engine has a lower median, the middle request time when observations are sorted, in your first run. A second run narrows or reverses that lead. Quoting only the first result would leave out evidence relevant to the customer’s decision.

We’ll compare repeated runs, calculate clearly defined speed ratios and examine the variation. You’ll learn what the measurements support, when the result remains uncertain, and which follow-up run would be useful.

02 / Worked example · planned

The comparison to build

Compare several independent runs of the orders benchmark. Keep warm-up and reset conditions recorded, and distinguish the ratio of medians from other possible summaries.

03 / Experiment · planned

How the lab will work

  1. Repeat the experiment with a recorded reset procedure and rotated execution order.
  2. Inspect raw samples, run-level summaries and unusual observations.
  3. Estimate the difference and its uncertainty using a method whose assumptions are explained.

The executable lab, reference outputs and progressive hints will be added when this chapter is implemented.

04 / Design task

Start your benchmark brief

Write a conditional comparison claim. Explain what variation remains and what further experiment would help resolve it.

05 / Keep the evidence

What your record should contain

  • All samples and their run identities
  • Reset, execution-order and environment records
  • Calculation method, assumptions and uncertainty estimate

06 / Interpret

What the evidence can support

Closely spaced samples can be dependent. More samples from one run do not automatically replace independent repetitions. Statistical evidence and customer relevance are separate questions.
