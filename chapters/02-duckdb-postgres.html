DuckDB or Postgres?

What does a first database comparison show, and what should you check before recommending either option?

This is a chapter outline. The worked example and executable lab are planned. You can use the design task below to start your benchmark brief.

What you will learn

  • Run a lookup and an aggregation against the same orders dataset.
  • Check that both engines produce equivalent answers.
  • Write an initial finding tied to the measured conditions.

01 / The question

Start with a customer decision

A customer needs both individual order lookups and monthly revenue totals. You want evidence about which database suits those jobs.

02 / Worked example · planned

The comparison to build

Compare DuckDB-Wasm and PGlite, a browser build of Postgres, using one generated orders dataset. Introduce the two queries before the performance results.

03 / Experiment · planned

How the lab will work

  1. Load identical data and record engine versions, storage and configuration.
  2. Verify answers, then measure startup, loading and query execution separately.
  3. Change the dataset size and retain both run records.

The executable lab, reference outputs and progressive hints will be added when this chapter is implemented.

04 / Design task

Start your benchmark brief

Write your initial recommendation and three questions you would investigate before using it in a customer discussion.

05 / Keep the evidence

What your record should contain

  • SQL, dataset generator and expected answers
  • Engine configuration and timing boundaries
  • Raw observations and the initial recommendation

06 / Interpret

What the evidence can support

Browser-build measurements describe those builds and conditions. Later chapters will revisit fairness, workload choice and uncertainty. Native/server runs will supply deployment evidence.
