Benchmark the complete pipeline

Does changing one component improve the complete customer outcome?

This is a chapter outline. The worked example and executable lab are planned. You can use the design task below to start your benchmark brief.

What you will learn

  • Define end-to-end completion across storage, Kafka and a database.
  • Locate queues, backpressure and limiting stages.
  • Measure recovery and verify the final data under continuing load.

01 / The question

Start with a customer decision

Files arrive in object storage, become events, and are written into a database. The customer needs to know when the uploaded records can be queried.

02 / Worked example · planned

The comparison to build

Trace an S3-compatible upload through an ingestion worker, Kafka, a sink worker and a database query. Record the adapters, transformation, retry behaviour and offset-commit policy.

Planned reference pipeline
  1. S3-compatible object storage
  2. Ingestion worker
  3. Kafka
  4. Sink worker
  5. Database and verification query

03 / Experiment · planned

How the lab will work

  1. Correlate run, object and record identities from upload submission to verified queryable output.
  2. Slow one worker and measure stage activity, backlog and the end-to-end outcome.
  3. Restore the worker while arrivals continue; verify values and detect missing or duplicate records.

The executable lab, reference outputs and progressive hints will be added when this chapter is implemented.

04 / Design task

Start your benchmark brief

Change one component or configuration. Design a repeatable comparison to establish whether it improves queryable-data delay or sustainable pipeline throughput.

05 / Keep the evidence

What your record should contain

  • Topology, versions, worker configuration and complete commands
  • Correlated observations, verification cost and query-polling interval
  • Backlog, retries, recovery history and final correctness checks

06 / Interpret

What the evidence can support

Measure end-to-end latency directly: stage p99 values cannot be added to produce an end-to-end p99. State clock assumptions and detection delay. A local topology supports claims about that tested deployment.
